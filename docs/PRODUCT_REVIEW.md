# Section Infi：产品审视与版本决策

## 目前最影响真实感的地方

1. **票种和实体开本混在一起。** 一种票不是一包货；同一款在店内可能同时有几个已拆开本、零散票和密封库存。玩家应先看票种，再从实际露出的票里挑。
2. **刮票只有“能不能刮”，缺少工具选择。** 单张用硬币有仪式感，连续刮十几张时需要更宽的刮片；效率差异应来自刮口宽度，而不是自动揭票。
3. **界面替玩家判断中奖。** 中奖格加边框、发光或自动结论都会破坏找奖过程。刮开阶段只呈现印刷内容，结果一律延后到柜台核验。
4. **货架扩展性不足。** 四张大卡片还能浏览，30–50 种票必须支持当日上架抽样、价格/玩法筛选和数据驱动的票面主题。
5. **整本概率容易被说得过度精确。** 发行比例、某一奖组总票数、单本观察样本是三种不同证据。游戏必须把“官方事实”和“体验模型”分开标注。
6. **对白虽然随机，仍缺少上下文记忆。** 老板应记得玩家是不是第一次来、是否连续加购、已经刮了几张、刚才是否回本，并据此选择对话。

## 确定的版本拆分

### v0.3 — 柜台选票与刮奖工具

- 同一票种生成 2–4 个同时在售的开本。
- 玩家可以从柜台露出的单张中选，也可以让老板代拿 1/3/5 张。
- 整本购买移到独立“问老板”区域，只从密封库存取货。
- 增加硬币、小号刮片和宽口刮铲；刮口不同但都需要持续操作。
- 去除中奖格的边框、发光、动画和颜色提示。

### v0.4 — 真实票库与分布说明

- 以官方公开资料建立 30–50 种票的目录。
- 每种记录面值、主题、配色、玩法、中奖机会、最高奖、奖级数和证据等级。
- 普通单本按小奖张数、百元档频率、单本返奖区间建模；大奖尾部单独建模。
- 当日门店只随机上架其中一部分，避免“每家店永远满货”。

### v0.5 — 逛街剧情与低成本对白

- 先用本地状态机完成剧情和上下文对白，运行时 Token 消耗为零。
- 大模型只作为未来可选增强，不参与随机数、奖项、预算或兑奖。
- 接入前先给出按每次游玩轮数计算的 Token 与费用上限。

## 后续候选功能

- 刮屑随移动方向堆积，以及根据速度变化的程序化摩擦声。
- 店员熟悉度、排队顾客、商场闭店提醒和天气事件。
- 收藏册：只记录玩家见过的票面主题，不记录或暗示“热号”。
- 可复现的模拟种子与公开蒙特卡洛报告，帮助校验长期返奖率。
- 无障碍模式：降低动画、放大票面文字、键盘刮票辅助。

## v0.7 Section Infi 复盘

本轮把“看起来像中奖”和“机器说中奖”收束为同一个数据源：票先生成可见格，随后立即用公开玩法反算；只要反算奖金与计划奖金不相等，生成过程就直接报错。兑奖阶段再次运行同一可见票面判定，因此不能再依赖隐藏金额兜底。

同时确定三条长期产品原则：

1. 数字玩法保持数字、指定文字奖符保持文字，实物图案玩法一律用统一 SVG 图符；
2. 官方完整奖组可以精确建模，但不能被描述成“一整本必定有几个奖”；
3. UI 分支必须改变信息架构、空间隐喻和操作节奏，单纯换主题色不算独立版本。
