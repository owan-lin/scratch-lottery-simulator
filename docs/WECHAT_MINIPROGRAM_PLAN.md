# 微信小程序迁移路线

## 目标与结论

本项目采用“同一票库与验奖规则、两个原生客户端”的结构：

```text
app/ticket-catalog.ts ─┐
app/prize-model.js     ├─ scripts/sync-miniprogram-core.mjs
app/ticket-engine.js  ─┘                │
                                         ▼
                                miniprogram/shared/*
                                         │
               ┌─────────────────────────┴────────────────────────┐
               ▼                                                  ▼
        网页端 React 客户端                               原生微信小程序客户端
```

彩票结果在整本生成时确定。小程序验票时重新调用 `evaluateVisiblePrize`，只读取玩家看见的中奖号码、图符和金额；隐藏的计划奖金只用于一致性断言，不参与结算。

当前已完成可导入微信开发者工具的 `0.1.2-mp` 版本。它不依赖服务器、不要求微信登录，也不连接真实支付、彩票购买或兑奖系统。

## 第一阶段：本地原生版（本次已完成）

- 原生目录：`miniprogram/`
- 商场进入、成年确认、5—10000 元预算
- 每次随机上架 14 款，保留缺货、多个开本与密封整本
- 玩家挑露出的单张、老板代拿 1/3/5 张、单独购买密封整本
- 硬币、小刮片、宽刮铲；Canvas 2D 按触摸轨迹逐步擦除
- 灰底黑字奖面，不在中奖位置增加高亮
- 刮完才进入柜台，按票面重新验奖
- 奖金可以兑进模拟钱包，或留作下一次换票
- 60 款票库、奖池和验奖规则由网页主版本生成，不手工复制
- 票面与网页端逐票种、逐奖级、整本固定种子交叉验证

微信基础目录、`app.json` 页面注册和页面文件约定见[官方项目结构文档](https://developers.weixin.qq.com/miniprogram/dev/framework/structure.html)；刮膜使用[官方 Canvas 组件](https://developers.weixin.qq.com/miniprogram/dev/component/canvas.html)的 `type="2d"` 节点。

## 第二阶段：开发者工具真机调优

项目已配置小程序 AppID `wx6ea3bd67ad8d311a`，接下来完成以下工作：

1. 用最新版微信开发者工具导入 `miniprogram/`。
3. 在 iPhone、主流安卓机各测试至少一轮：
   - Canvas 首次初始化、横向移动、连续刮 20 张；
   - 刘海屏与底部安全区；
   - 低端机整本生成耗时和内存；
   - 60 款票的长名称、组合玩法与九宫格布局；
   - 前后台切换后 Canvas 是否需要重绘。
4. 若启动生成整本在低端机超过 500ms，把票面从“开本时一次生成”改成“奖池先生成、售出时按票号种子惰性生成”，且保持结果确定不变。
5. 根据真机截图逐款调整票面高度与图符尺寸。

开发者工具的项目配置字段见[官方 `project.config.json` 文档](https://developers.weixin.qq.com/miniprogram/dev/devtools/projectconfig.html)。

## 第三阶段：发布前产品与合规处理

这是发行路径里最需要谨慎的一段。即使游戏没有真钱，彩票主题也可能触发平台对赌博、彩票销售或彩票预测内容的审核：

- 保留首屏和票面上的“仿真练习票 / 无兑奖价值 / 不使用真钱”；
- 不接微信支付、广告换筹码、充值、提现或任何真实彩票跳转；
- 不提供选号、走势、中奖预测、购买建议或“回本技巧”；
- 不把模拟结果描述为现实彩票的可预测规律；
- 保留 18+ 确认和理性购彩提示；
- 商店简介优先使用“概率教育与刮卡交互模拟”，避免“赚钱”“稳赚”“真实投注”等表达；
- 提审前在微信公众平台工单中确认应使用普通小程序还是小游戏类目，以及彩票主题模拟内容能否过审。

微信曾明确禁止小程序中的“彩票预测”宣传及预测商品销售；本项目当前没有此类功能，但正式发布仍应以提交时的最新平台答复为准。

若审核要求将互动游戏归入“小游戏”，共享规则文件仍可复用，只需要把 WXML 页面外壳迁到小游戏 Canvas 场景，不需要重写票库或验奖算法。

## 第四阶段：可选云能力

首版不需要后端。只有出现以下需求时才接入云开发：

- 跨设备保存进度；
- 好友成就或排行榜；
- 版本公告、热更新票种配置；
- 匿名性能与崩溃统计。

接入时必须把 AppSecret 留在云函数/服务端，绝不能写进小程序包。若采集任何用户信息，还要补隐私保护指引、授权说明和数据删除路径。当前版本只在本机保存刮具偏好，不采集用户资料。

## 日常维护流程

网页主版本仍是规则源。修改票库或验奖逻辑后执行：

```bash
npm run sync:miniprogram
npm run check:miniprogram
npm test
```

`sync:miniprogram` 会：

1. 把 TypeScript 票库序列化成小程序可用的 CommonJS；
2. 把奖池和验奖引擎转换为 CommonJS；
3. 同步本地图符雪碧图；
4. 在 `--check` 模式下拦截忘记同步的提交。

不要直接编辑 `miniprogram/shared/`，这些文件带有自动生成标记。

## 如何在微信开发者工具中试玩

1. 安装并打开微信开发者工具。
2. 选择“导入项目”。
3. 目录选本仓库的 `miniprogram/`。
4. 确认开发者工具显示 AppID `wx6ea3bd67ad8d311a`。
5. 编译后会直接进入商场彩票店场景。

## 上传开发版本

仓库使用微信官方 `miniprogram-ci`，上传密钥必须保存在仓库外，并通过环境变量临时传入：

```powershell
$env:WECHAT_PRIVATE_KEY_PATH='你的上传密钥绝对路径'
$env:WECHAT_UPLOAD_VERSION='0.1.2'
npm run upload:miniprogram
```

上传前先执行 `npm run check:miniprogram`。微信公众平台的“小程序代码上传”IP 白名单必须包含执行上传的公网 IP。仓库已忽略 `*.key`，任何上传密钥、AppSecret 或访问令牌都不得提交到 GitHub。

使用同一组环境变量执行 `npm run preview:miniprogram`，可在忽略提交的 `outputs/` 目录生成微信官方预览二维码。预览码仅供该小程序的管理员、开发成员和体验成员扫码。

`0.1.2` 已于 2026-08-08 成功上传为开发版本；上传开发版本不会自动提交审核或发布。

正式预览码、体验版和提交审核必须使用用户自己的微信小程序账号与 AppID；代码仓库无法代替这一步。
